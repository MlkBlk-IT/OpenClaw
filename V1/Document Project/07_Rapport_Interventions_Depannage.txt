2.1. Diagnostic WhatsApp (20:09)
PROBLÈME : WhatsApp ne répond pas, Telegram OK.
ANALYSE : Lecture des logs OpenClaw (%LOCALAPPDATA%\Temp\openclaw\).
CAUSE RACINE : 
  - La session WhatsApp avait accumulé 23 806 tokens de contexte
  - Groq free tier = 12 000 TPM max → erreur 413 "Request too large"
  - Les fallbacks suivants (gemini-3.5-flash 429, qwen3-32b 404, llama-4-scout 404)
    brûlaient ~60 secondes avant que mistral-large ne réponde
  - Pendant ce temps, le pont WhatsApp Web abandonnait le tour
  - Log clé : "visible channel turn dispatched with no queued reply payloads"
RÉSOLUTION : 
  - Commande /reset dans le chat WhatsApp pour purger le contexte
  - Réponse revenue en <2s via mistral-large
LEÇON : Le contexte de session doit être surveillé; au-delà de 12k tokens, 
        Groq free tier échoue systématiquement.

5. LEÇONS APPRISES
--------------------------------------------------------------------------------

5.1. Groq free tier et contexte
  - Limite TPM (Tokens Per Minute) = 12 000 pour llama-3.3-70b
  - Si le contexte de session dépasse ~5 000 tokens, Groq rejette avec 413
  - Solution : purger le contexte (/reset) ou utiliser Mistral (quota plus souple)

5.2. LM Studio et JIT loading
  - justInTimeModelLoading=true : l'API /v1/models liste le catalogue complet
  - Seule la commande 'lms ps' montre les modèles réellement en RAM
  - preload=false : LM Studio gère lui-même chargement et Auto-Evict
  - Filet de sécurité : même sans modèle résident, le JIT charge à la 1ère requête

5.3. Tâches planifiées Windows
  - -LogonType S4U incompatible avec comptes locaux → utiliser Interactive
  - Trigger AtLogOn préféré à AtStartup pour LM Studio (besoin de session utilisateur)
  - Toujours tester avec Start-ScheduledTask après création

5.4. WhatsApp Web et timeouts
  - Le pont WhatsApp abandonne les tours >30s sans réponse
  - Si le fallback met 60s (modèles morts + rate limits), la réponse est perdue
  - Solution : réduire le nombre de fallbacks ou augmenter la vitesse du PRIMARY

5.5. SOUL.md et annonce du modèle
  - Le modèle annonce le PRIMARY théorique au lieu du modèle réel
  - Fix : ajouter règle "Annoncer le modèle RÉEL utilisé à la fin de chaque réponse"
  - Résultat : *(Modèle réel : mistral/mistral-large-latest)*
